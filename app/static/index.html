Peak is a 6× surge with rising latency; Error injects 5xx responses with exceptions and matching error logs; Normal restores a calm baseline.

Infrastructure on host Use case 2 · Ops / SRE

Host trouble on the Docker host that runs every site, with the knock-on effects in the applications. Metrics land on the host resource as Demo datasources with alert thresholds; kernel and systemd logs land on host; every service gets slower and some requests fail, with logs that carry the trace id.

Memory pressure and swap storm

Available memory falls to 4 %, swap use climbs past 90 %, thousands of pages a second swap in and out, then the OOM killer takes postgres. Checkout and API latency climb 5× and database pools exhaust.

Network degradation

Packet loss on eth0 reaches 18 %, latency jumps from 0.4 ms to 140 ms, TCP retransmits and interface errors spike, the edge proxy times out dialing origins. Users see resets and 503s.

CPU saturation, zombies and thread storm

Load average climbs past 60, context switches hit 900k/s, a worker leaks hundreds of zombie processes and 30k threads, the scheduler throttles. Event loops block, requests time out.

Start here: Infrastructure Alerts
  1. Infrastructure RCA dashboard: the host graphs bend first, the service latency and error graphs below bend with them.
  2. Alerts: the Demo thresholds fire on host within a few minutes.
  3. Open a slow trace, then Logs on host at the same minute: the kernel line explains it.

Business impact Use case 3 · Executives

Nothing is wrong with the infrastructure. The sites are up, the host is healthy, yet money and leads are being lost. Business KPIs are pushed per site as a Demo: Business KPIs datasource with thresholds, with the traces and logs that explain why.

: checkout fails

The payment gateway call to times out after 30 s. Checkouts return 502, conversion collapses from 97 % to near zero, revenue per minute goes with it, cart abandonment climbs. Site availability stays green.

: a call-to-action link is a 404

Every click on () lands on a 404. RUM records the click, the failed outbound link and the JS error; referral traffic drops to zero. No server is involved at all.

: signups silently lost

The signup form keeps returning 200, but the SMTP connection to is refused, so no confirmation email goes out and leads are lost while traffic looks perfectly normal. Only the business metric and a warning log reveal it.

Start here: Business
  1. Business Impact dashboard: sites are up and the host is calm, yet revenue, conversion or leads fall.
  2. Business alerts fire on the site's resource (conversion, CTA success, confirmation rate).
  3. Traces: the 502 checkout with the 30 s payment-gateway span; Logs: the matching error with the order id.
